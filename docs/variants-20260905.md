# September 5: custom variants silently lose vehicle settings

The user selected a saved custom game type but still saw no Ghost or Scorpion.
The current emulator save, New003, contains vehicle set 0 (All) at offset 0x48.
Blood Gulch contains both vehicle tags/models and their scenario placements.

## Cause

Halo 3925 stores a 104-byte variant, followed by a 20-byte XAPI title signature,
inside the 512-byte `blam.lst`. The existing `XCalculateSignatureBegin` compatibility
stub returns INVALID_HANDLE. Halo's helper at 0x2D120 consequently leaves the
signature output untouched. The observed custom save has a zero signature; all
26 generated default playlist records contain leftover save-path bytes there.

The original loader at 0x2F800 recomputes that signature into stack scratch memory.
On mismatch it calls 0x1015A0 to generate default Slayer, copies in the saved name,
and returns success. Thus the menu can display the user's custom name while the
match uses Warthogs/default settings. This failure precedes the solo-start shortcut.

## Local change

`tools/recomp.sh` maps 0x2D120 to `HaloSignSavedRecord`. For 104-byte variants it
computes the flags=0 title HMAC using the existing derived key and SHA implementation.
Other record sizes retain the original XAPI call sequence and unsigned-profile
compatibility, including leaving output untouched if Begin fails.

Full `blam.lst` reads recover only the two observed old signatures: all zero, or a
zero DWORD followed by printable Xbox `u:\`/`z:\` path residue. Recovery checks name
termination, game/vehicle/weapon enums, team setting and health bounds, then repairs
the signature in the guest copy. Disk files, names and all options stay unchanged.
Other signatures retain Halo's normal validation; arbitrary malformed data is not
re-signed. Newly saved variants receive real signatures and need no recovery.

## Validation

`make -C recomp/host test-variants` runs the original generated 0x2F800 loader with
synthetic saved records. It reproduces renamed/default Slayer using the old stub,
then verifies that every byte of the custom settings survives with the fix for all
five vehicle-set values. It also checks an independent Python HMAC, rejection of
damaged signed records and invalid vehicle enums, old playlist recovery, fragmented
guest input/output, stack/register ABI, and both unsigned and enabled XAPI fallback.
AddressSanitizer and UndefinedBehaviorSanitizer pass.

NT I/O tests check that recovery is limited to complete 512-byte variant reads at
offset zero; short/partial reads and profiles do not enter it. Existing file-open,
file-I/O and SHA/key-derivation tests pass. Native build passed. In the emulator, New003 is recovered, selected through
System Link / Blood Gulch and started with the existing solo shortcut. The user confirms both the tank and Ghost work in that emulator session.
The pause menu selects Leave Game with the D-pad. The combined build was deployed
over USB at 22:06 CDT, with direct-read and remount verification. See the
[deployment record](split-screen-20260905.md). Hardware confirmation is pending.
