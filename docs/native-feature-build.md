# Native collision-feature preparation

Status: perf322 is installed on the physical Vita, currently on the dashboard.
The optional vertex experiment is disabled after hardware counters showed its
large-list admission did not match the beach workload. Surface and query-scope
work below is local only; no new hardware FPS benefit is established.

The entries below are a chronological development record. Earlier statements
about missing integration describe the state at that point in the work.

The current target is the `868F0` feature-building closure beneath the biped
collision chain. Existing `xk_native_4b9d0.c` already replaces the BSP sphere
query (`88110`) and solver feature tests (`864C0`); do not duplicate those.
Older Pi measurements put feature construction at 9.5% of `4B9D0`, so this
candidate alone is not expected to close the full 20 FPS gap.

## Evidence and reference

Perf318's final five sampled windows attribute 67.3% of type-update elapsed
time to `4C980`, 13.2% to `44AD0`, and 8.7% to `39450`. These are sampled,
nested elapsed shares, not full-frame CPU percentages. The known biped chain
is `4C980 -> 4B9D0 -> 49600 -> 172BF0 -> 171F10`.

`tools/extract_feature_build_reference.py` lifts the owned executable with
`NoGameHooks`, walks direct dependencies, and rejects indirect dependencies.
It refuses an output directory inside the source repository. The extracted
13-function reference and manifest stay in the private directory
`../feature-build-native-319/reference/`.

The first reference checks in `tools/tests/feature_build_reference.c` pass on
the host under ASan/UBSan and on the physical Pi as ARM32 Cortex-A9 Thumb code.
They cover empty result lists and one untransformed world vertex, checking
position, flags, material, radius, output count, callee-saved registers and
stack cleanup. The expanded fixture now passes 288 cases on both host ASan/UBSan and physical
Pi ARM32: empty/one-vertex lists, sphere and capsule counts of 0/255/256,
zero/two-unit extrusion, absent/identity/translated/scaled-rotated transforms,
and world/object ownership. Transform expectations are hand-computed; object
features retain the object handle and use the absent world-surface sentinel.
It verifies independent capacity limits, appended
sphere/capsule metadata, positions, radius, extrusion direction, and stack
cleanup. These checks do **not** cover the whole closure's correctness, aliasing,
general edge/surface features, arbitrary floating-point inputs, or a native candidate.

## Contract for the replacement

- Preserve the original vertex, edge, then surface order and first-match rules.
- Preserve feature capacities and metadata, including signed index behavior.
- Retain transformed object geometry; initially unsupported cases must fall
  back before any guest mutation, rather than silently losing features.
- Preserve floating-point order and observable register, flag, stack, memory,
  and scheduling effects at the replacement boundary.
- Validate physical aliases, stack overlap and page translations before
  caching pointers or capturing inputs. Guest addresses alone are insufficient.
- Keep query ownership, actor guards and publication boundaries unchanged.

Next expand the oracle cases to edges, surfaces, general transforms,
and awkward memory layouts. Then implement the closure with explicit native
inputs/results, compare full observable state against the oracle on host and
Pi, and test a qualified candidate in ordinary Vita gameplay. Keep the original
path as fallback and preserve a rollback build.

## Native point/vector transforms and vertex input path

`xk_feature_transform` replaces the numeric point/vector operation order of
B5EA0/B5E40 with direct double intermediates and float outputs, including the
unit-scale branch and optional translation. Inputs must meet the existing
finite/default-FP/disjoint-matrix contract. Point/output aliasing is supported
by capturing all input coordinates before the first output store.

`xk_feature_vertex_from_geometry` now performs checked vertex -> incident edge
-> surface metadata lookup, applies the native transform if supplied, and calls
the native vertex writer. The 288 original vertex cases now compare this
combined geometry path with 868F0, rather than feeding hand-computed transformed
positions to the output writer. Native transform outputs additionally match
B5EA0/B5E40 in 20,000 deterministic finite point/vector cases, including unit
scale and in-place output, on host ASan/UBSan and physical Pi ARM32. Prior
30,000 writer comparisons and surface traversal tests remain passing.

This still does not replace the complete guest closure: signed plane lookup,
plane transforms, edge convexity selection, complete query-list sequencing,
physical memory checks and full guest execution-state handling remain required.
Perf318 has not been replaced; these are implementation/correctness results,
not timing results.

## Guest-boundary audit before integration

The 1,000 mixed-query fixtures now seed nonzero registers, lazy flags and x87
slots and rotate entry x87 TOP through all eight values. Output comparisons
continue passing on host ASan/UBSan and physical Pi ARM32. Observed changed
register mask is 0x17 (EAX/ECX/EDX/ESP); EBX/EBP/ESI/EDI, TOP, FCW, MMX and SSE
remain unchanged in these cases. ECX returns the surface count because the
original reuses its pushed ECX slot as a counter; EAX returns the surface count
when nonempty, otherwise the edge count. A generic callee-saved-register stub
would not reproduce this behavior.

Across this sample, all eight x87 slots changed in at least one TOP configuration,
FSW changed in 911 cases, lazy flags in all 1,000, changed scratch-stack bytes
reached ESP-232, and budget use reached 176 backedges. These are sampled changed
bytes, not an exhaustive write-footprint or upper-bound proof. Writes that
restore the same value are invisible to this check. Original guest memory
ordering, physical aliases, preemption, and these execution-state effects
remain unimplemented in the output-only candidate.

Actual perf318 call sites are in private `build-x87/recomp/code_028.c` at
171FC3 and 173044 (plus the fused copy). 171FC8 immediately rewrites flags;
173049 onward overwrites EAX/EDX/ECX, but this local inspection does NOT establish
whole-program liveness or justify dropping guest state. Preserve the existing
motion guard at the 868F0 entry and phase observers when adding a hook. Next
implement/verify the boundary using the existing native-collision journal and
layout-validation patterns; do not deploy a raw output-only call replacement.

## Physical memory admission primitives

`recomp/kernel/xk_feature_memory.h` adds contiguous guest-to-host span validation
and physical-range overlap checks. It checks page-table extent, 32-bit guest
address wrap, arena bounds, page alignment and every page in a span. Fragmented
mappings decline. Layout checks reject output/scratch-stack aliasing with each
other or cached read spans, even when guest addresses differ. Read/read aliases
are permitted. Failed span validation leaves its result unchanged.

`tools/tests/feature_build_memory.c` passes under host ASan/UBSan and physical
Pi ARM32: contiguous cross-page spans, split pages, two distinct guest ranges
mapping the same physical bytes, stack/read collisions, range overflow and
82,944 byte-oracle interval comparisons. This is a primitive-level test, not a
complete runtime admission gate. Allocation ownership, mapping lifetime, active
page-table selection, collection of all protected spans and the full scratch
write bound still require integration. Guest register/FP/stack reconstruction
remains outstanding; no native entry hook or Vita build was deployed.

It currently delegates point transformation and feature emission to the

Host ASan/UBSan and physical Pi ARM32 both passed 1,000 complete query

## Emitter admission and checked-memory qualification

`xk_feature_admission.h` now validates the emitter's output, eight-byte saved
stack area, arguments, point and zero constant through the active page table.
It rejects render-view mappings, bad stack arithmetic, noncontiguous/out-of-arena
spans and physical write/read aliases. It requires default guest FP control and
the unchanged zero constant. In checked builds it refuses policy-controlled
pages and diagnostic watch ranges before touching them, and conservatively
stamps the output span after successful native writes. Caller-provided extents
must be real; allocation ownership and mapping lifetime remain caller duties.
No entry hook or worker dispatch is installed by this header.

The emitter callback now exercises this admission path in the reference tests.
Host ASan/UBSan and physical Pi ARM32 pass both ordinary and checked builds.
Twelve refusal cases leave the full context/3 MiB arena unchanged; checked
builds add three trash-page/watch/MMIO refusal cases and verify zero epoch
changes on refusal. Successful checked calls explicitly reset then verify all
output page stamps, alongside existing output/state tests. The checked fixture
uses diagnostic callbacks, not the complete Vita memory-policy implementation.

Next measure the complete admitted emitter against its original reference,
including validation and state restoration, before deciding hook granularity.
Repeated per-vertex validation may erase arithmetic savings; prefer validating
immutable query spans once where ownership permits. Edge/surface boundaries
still need native state integration for a whole-query replacement. Hardware
remains perf318, with no new frame-time result or package from this work.

This is a fixed-input warm-cache microbenchmark; it does not model campaign
cache traffic, production hook overhead, scheduling or Vita frame time.

## Scoped vertex admission implemented

`xk_feature_scope.h` validates the query's vertex list, collision geometry
header and vertex/edge/surface arrays, optional matrix, constant, output and
full vertex-pass stack footprint once. Counts/links and finite inputs are
checked before mutation. Physical overlap with stack/output is refused. The
geometry tag-block count/pointer offsets match the reference type declarations
at `private-references/stianeklund-halo/src/types.h` (collision_bsp_t): surfaces
0x3c/0x40, edges 0x48/0x4c, vertices 0x54/0x58. Runtime allocation ownership
and live mapping lifetime remain requirements at the eventual hook site.

The state driver now supports explicit opaque callback context; no TLS/static
cache is used. The scoped pointer is consumed only in the vertex phase.
Admission requires budget >= vertex count: its n-1 original backedge decrements
remain intact, and no scheduling yield can occur within that admitted phase.
Edge/surface processing remains original and may yield after the scope's last
use. An emitter refusal after a transformed nonfinite result invokes the

## Mixed queries and large geometry tables

The reference suite now runs the scoped path against 1,000 mixed queries with
vertices, edges and surfaces: 785 admit and 215 decline. Every admitted result
matches complete context and all 3 MiB of arena memory; every decline leaves
entry unchanged before the original fallback, which then matches too. Host
ASan/UBSan and physical Pi checked ARM32 pass. This exercises original
edge/surface callbacks after the scoped vertex phase, with the normal large
preemption budget. Actual yields and concurrent mapping lifetime are still
not covered by this fixture.

The query timing harness accepts `FEATURE_TABLE_SIZE=64..16384` and places
its geometry arrays separately to avoid accidental overlap. At 16,384 entries
per table, validating full arrays costs enough to lose short-list benefits.
Narrow range validation was implemented, but an unconditional range walk
also made long lists slower. The current heuristic narrows when estimated
array pages exceed eight times the queried vertex count; otherwise it uses
whole mapped spans. Range dependencies are validated vertex -> edge ->
surface before following indices; final physical overlap checks remain.
This is a tuning heuristic, not a hardware-qualified performance rule.
