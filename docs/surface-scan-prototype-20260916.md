# Bounded visible-surface scan prototype

Historical prototype: the later [scene-index implementation](native-scene-index-run.md)
is qualified and enabled in current hardware tests. Do not mistake the parked
prototype below for the current runtime or repeat its completed run census.

This is an **uninstalled experiment**, with no production recompiler hook,
runtime switch, Makefile integration or FPS claim. The current Vita still runs
the original loop. The helper is in `recomp/kernel/xk_surface_scan.h`; its only
caller is the comparison generated by `tools/test_surface_scan.py`.

The latest native-resolution Blood Gulch phase trace puts selected self time
in the ordered scene callback routine `54010` at 10.198 ms/frame. That includes
uninstrumented descendants and draw handling: it is **not** the cost of this
scan. The candidate targets only the `54132..54141` loop, which advances over
signed surface indices below the current material threshold. Callbacks, draw
order, material setup and the rest of `54010` are outside the prototype.

## Contract and remaining integration work

Within one mapped page, the helper scans up to 128 aligned entries, leaving at
least one original scheduler-budget unit. It publishes the exact EBX, ESI,
budget and lazy subtraction-flag payload at the original backedge. The original
loop retains the final iteration and every possible scheduler handoff. A
decline leaves the complete context unchanged. The original function's captured
arena and page-table roots must be passed to the helper.

This requires ordinary RAM whose contents cannot change concurrently during a
batch. It does not establish ownership merely by checking an address. Before
production integration, verify the caller's source lifetime and worker boundary,
guard the full image and emitted loop shape, retain interior dispatch entries,
and measure run lengths on hardware. No shared lock or worker policy has been
changed. Synthetic long-run instruction savings alone do not justify enabling it.

## Exact-state and cost checks

The tool independently lifts the original loop from the owner's supported
Halo executable. Both the whole image and the containing function/loop spans
are checked. Generated original code and owned bytes stay outside the repo.

The final inline/gated variant passes:

- 1,540 host comparisons under ASan/UBSan, including complete context, guest
  arena and page-table equality; 191 batches and 14,837 matching yields.
- 62 Vita SDK ARM comparisons, including complete context, arena, page tables,
  native FPSCR and yield count. These use an instruction harness, not Vita3K
  or physical frame timing.
- Empty/short/long runs, signed thresholds, unaligned and wrapped cursors,
  page edges, a bound aliasing scanned memory, and yields that change the
  threshold, bound, cursor, stack, page mapping or next source value.

The first external-call version regressed badly on short/fallback paths.
Inlining and an every-eighth-backedge admission check reduce that overhead,
but do not eliminate it. Representative final instruction counts are:

| Input | Original | Candidate | Change |
| --- | ---: | ---: | ---: |
| 1 matching entry, ample budget | 73 | 96 | 31.5% more |
| 3 matching entries, ample budget | 115 | 164 | 42.6% more |
| 16 matching entries, ample budget | 388 | 455 | 17.3% more |
| 128 matching entries, ample budget | 2,740 | 1,239 | 54.8% fewer |
| 512 matching entries, ample budget | 10,804 | 4,746 | 56.1% fewer |
| 4,096 matching entries, ample budget | 86,068 | 36,986 | 57.0% fewer |
| 512 unaligned entries, ample budget | 10,804 | 17,470 | 61.7% more |
| 512 entries, low budget with page relocation at yield | 13,587 | 16,562 | 21.9% more |

Counts include the fixture's batch accounting. They exclude physical cache,
kernel scheduling and GPU behavior. The yield handler deliberately resets to
a small budget in the low-budget cases. These mixed results do not justify
shipping the candidate. A cheap once-per-run fallback and measured actual run
distribution are the next requirements.

Reproduce with an owned image and manifest:

```sh
python tools/test_surface_scan.py --xbe /path/to/default.xbe \
  --manifest /path/to/game_manifest.json --out /private/new-host-run --sanitize
python tools/test_surface_scan.py --xbe /path/to/default.xbe \
  --manifest /path/to/game_manifest.json --out /private/new-arm-run --arm
```

Each output directory must be new. The ARM check uses Vita SDK GCC and the
existing Python ARM comparison dependencies; `ARM_CC` can override its path.
Private receipts are `surface-scan-gated-asan.log` and
`surface-scan-gated-arm/result.json` beneath the current direct-query validation
directory. Earlier failed/slow probes remain there for comparison.
