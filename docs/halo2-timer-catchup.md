# Preserve overdue Halo 2 timer callbacks across service turns

Native212 completed the fixed sound commit and then tripped the H2 timer adapter's 64-callback drain guard. The final observed `484248` deadlines still advanced by `200000` units of 100 ns (20 ms). A captured 1.628-second service gap left genuine overdue work; the last next deadline was still 368.120 ms behind its callback timestamp. The old guard mistook this finite catch-up sequence for an invalid queue. The original main menu remains unverified.

Original callback `332F4C` passes 20 to helper `332B6D`, which increments the existing 64-bit object deadline with carry and invokes `KeSetTimer` with timer `484248` and DPC `484270`. It does not replace the deadline with the current time. A private owned-code oracle executes all ten original helper instructions in 1,024 calls, including low-word carry, checking the exact four kernel arguments and nonvolatile registers/stack. That oracle captures and returns from the kernel boundary; it does not emulate the timer implementation or the callback's subsequent device work.

An expired absolute timer signals and queues its DPC using the actual current system time in the [pinned Cxbx expiration implementation](https://github.com/Cxbx-Reloaded/Cxbx-Reloaded/blob/585c49a50af1255ab155099e06f24505f9c5a800/src/core/kernel/exports/EmuKrnlKi.cpp). The [pinned DPC execution implementation](https://github.com/Cxbx-Reloaded/Cxbx-Reloaded/blob/585c49a50af1255ab155099e06f24505f9c5a800/src/core/kernel/exports/EmuKrnlKe.cpp) removes the queued mark before invoking the callback. Thus a callback can legitimately requeue itself while it executes. Duplicate insertion while still queued retains the first arguments, consistent with [Microsoft's queue contract](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-keinsertqueuedpc).

The H2-only adapter retains its 64-callback service budget but leaves the next queued record, arguments, FIFO sequence and timer deadline unchanged. The worker yields at its restored passive IRQL, then services pending work on its next scheduler turn. It does not sleep until a future timer when a DPC is already pending. Timer arm/cancel/direct insertion inside a DPC no longer boosts that already-running worker ahead of other ready threads; outside callers retain the wake-up behavior. Every original callback still executes completely at dispatch IRQL, with the existing strict stack, mapped-object, invalid-header and blocking checks. The fixed 64 timer/64 DPC record capacities remain unchanged. This is cooperative service scheduling, not exact emulation of NT interrupt latency or a watchdog that detects arbitrary infinite callback cycles.

Synthetic tests run the real worker through 195 callbacks with the original 20 ms catch-up pattern and an independently queued peer. They check all callback arguments/order, three passive service yields, eventual future rearm and no self-boost. A separate 193-callback direct-requeue sequence checks argument retention and duplicate insertion across the same turn boundaries. Full worker CPU/FP context and IRQL remain intact. Existing expiration, cancellation, signal-consumption, overflow, mapping and fault tests still pass, as do ASan/UBSan and all 54 H2 host executables. An initial new test harness had an uninitialized synthetic worker context and was corrected before the successful tests or native build; no failing build was launched.
