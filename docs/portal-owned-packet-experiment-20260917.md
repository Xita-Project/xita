# Portal preparation packet experiment, September 17

The private serial owned-packet oracle preserved a complete retained 532E0 traversal with two sibling portal preparations, including its context, guest memory, roots, FPSCR and ordered writes. Projection and clipping used the real retained ARM descendants. Budget and mapping/alias declines retained the original path before packet mutation.

This journaled transport is not being integrated. Four preparation calls needed 1,122 guest-write records, mostly scratch. A separately compiled capture/journal/commit model added 77,206 ARM instructions with mapping validation excluded, compared with 84,079 for the original entire traversal. No hardware performance conclusion follows from these counts.

The oracle captured state at each actual child entry. It did not prove that a future sibling's saved context can be committed after intervening recursion, nor did it qualify original host-context identity, production callbacks or a worker interface. A smaller caller-proven state contract would need separate evidence; dropping scratch or stale context fields by assumption is not acceptable.

Evidence remains private under `portal-owned-packet-prototype/`: report, object pins, complete oracle results, transport source and emitted-code measurements. No production defaults, pools, device or retained optimizations changed.
